Key Commands Structure │ │
│ │ │ │
│ │ 1. Project Initialization │ │
│ │ │ │
│ │ - /sc:load - Load project context │ │
│ │ - /sc:task create - Convert task breakdown to tracked tasks │ │
│ │ - /sc:analyze - Initial infrastructure analysis │ │
│ │ │ │
│ │ 2. Implementation Flow (Per Task) │ │
│ │ │ │
│ │ - /sc:implement - Execute specific tasks with verification │ │
│ │ - /sc:test - Run tests after implementation │ │
│ │ - /sc:analyze - Verify quality and security │ │
│ │ - /sc:task update - Track progress │ │
│ │ │ │
│ │ 3. Progress Monitoring │ │
│ │ │ │
│ │ - /sc:task status - Real-time progress view │ │
│ │ - /sc:task sprint-status - Sprint tracking │ │
│ │ - /sc:document progress-report - Generate reports │ │
│ │ │ │
│ │ 4. Quality Assurance │ │
│ │ │ │
│ │ - Pre-implementation checks │ │
│ │ - Auto-verification during implementation │ │
│ │ - Post-implementation validation │ │
│ │ - Continuous integration testing │ │
│ │ │ │
│ │ 5. Special Workflows │ │
│ │ │ │
│ │ - MCP integration with /sc:design and testing │ │
│ │ - UI components with /sc:implement --magic │ │
│ │ - Performance optimization with /sc:improve │ │
│ │ - Troubleshooting with /sc:troubleshoot │ │
│ │ │ │
│ │ Daily Workflow │ │
│ │ │ │
│ │ 1. Morning: Check task status │ │
│ │ 2. Before coding: Verify approach with best practices │ │
│ │ 3. During coding: Implement with test-driven development │ │
│ │ 4. End of day: Update progress and plan next tasks │ │
│ │ │ │
│ │ Benefits │ │
│ │ │ │
│ │ - Automated verification at each step │ │
│ │ - Best practices enforcement via Context7 │ │
│ │ - Progress tracking and visibility │ │
│ │ - Early problem detection │ │
│ │ - Consistent quality across implementation
